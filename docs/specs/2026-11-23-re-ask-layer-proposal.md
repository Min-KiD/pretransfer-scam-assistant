# Proposal: a re-ask layer for answers the assistant cannot use

Date: 2026-11-23. Status: **proposal, not approved by Minh.** No code, no measurements.

## Context

Decided on 2026-11-23 for the question-and-answer part:

- The model asks its own questions and concludes (`tu_do` of E2: 78.7% correct scenario vs 69.3% for code-chosen questions, 75 sessions).
- Three things stay in code:
  1. Hard limits: at most 3 questions, output constrained by a JSON schema (only a valid scenario id or `chua_du_can_cu`).
  2. Exact comparisons: account number in the image vs the account being paid, account label lookup.
  3. The M3 second opinion (classifier C0): if it disagrees with the model, the conclusion is downgraded to `chua_du_can_cu`.

The gap: today every question counts toward the 3, even when the user answers off-topic or misunderstands the question. The
model may ask again but loses a turn. Real users will drift more than the simulated one (in E5 the simulated user never went
off-topic; 22-31% of its replies contain "không biết / không rõ / không nhớ").

## Proposal

Each turn, next to `du_doan` and `cau_hoi`, the model returns a rating of the reply it just received:

| `tra_loi_truoc` | Meaning | What code does |
|---|---|---|
| `dung_duoc` | Answers the question | Counts one question, continue |
| `khong_biet` | The user says they do not know or remember | Counts one question, **no** re-ask of that question; the model moves to another point |
| `lac_de` | Talks about something else, or misunderstood the question | One **uncounted** re-ask; the re-ask must be shorter and come with quick-reply buttons |
| `mau_thuan` | Contradicts what was said earlier or the image | One uncounted confirmation question (the app already has this for an account number one character off) |

Limits kept by code; the model cannot relax them:

- Each question may be re-asked once. At most 2 uncounted turns per session, so a hard ceiling of 5 questions.
- If it is still unclear at the end: conclude `chua_du_can_cu` with the generic check-list. No guessing.
- A re-ask always carries quick-reply buttons (2-4 choices plus "Không rõ"), to cut a second misunderstanding.

Why no re-ask on `khong_biet`: asking again creates no new information, it only makes a user in a hurry skip the assistant.

## How to measure before keeping it

The current simulator cannot measure this layer, because the simulated user always answers the question. Needed:

- Three new user types in `sim/cases.py`: answers off-topic, misunderstands the question, answers in one or two words.
- Two arms on the same cases: with and without the layer.
- Measures: correct scenario, scam called ordinary, share of `chua_du_can_cu`, mean questions asked.
- Keep rule (declared in advance): on cases with the new user types, correct scenario rises by at least 5 points, and mean
  questions asked on the old cases does not rise by more than 0.3.

## Open

- Ceiling on uncounted turns: 2 (proposed) or 1.
- Whether `tra_loi_truoc` comes from the chat model itself (one call) or from a separate call (easier to audit, one more call).
- Whether quick-reply buttons are generated by the model or taken from a fixed per-scenario list.
